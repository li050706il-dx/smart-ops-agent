# 智能运维工单管理系统知识库

## 系统简介

智能运维工单管理系统面向校园、园区、企业设备运维场景，用于设备报修、工单派发、维修处理、巡检管理、通知消息和数据统计。

系统采用 Spring Boot 单体架构，集成 MySQL、Redis、RabbitMQ、MyBatis-Plus、Knife4j 等技术。

## 系统角色

系统包含四类角色：

- ADMIN：管理员，负责用户管理、设备管理、工单派发、巡检计划创建、统计查看。
- USER：普通报修用户，负责提交报修工单、查看自己的工单、取消工单、评价工单。
- WORKER：维修人员，负责接单、添加处理记录、完成工单。
- INSPECTOR：巡检人员，负责执行巡检任务、提交巡检结果。

## 设备状态

设备状态包括：

- 1：正常
- 2：故障
- 3：维修中
- 4：停用

如果设备状态为 2，表示设备存在故障，需要维修。
如果设备状态为 3，表示设备已经进入维修流程。

## 工单主流程

工单主流程如下：

1. 用户提交报修工单。
2. 系统使用 Redis 防重复提交。
3. 创建工单后，通过 RabbitMQ 异步通知管理员。
4. 管理员可以手动派单，也可以由系统自动派单。
5. 派单后，通过 RabbitMQ 异步通知维修人员。
6. 维修人员接单。
7. 系统使用 Redis 分布式锁防止同一工单被重复接单。
8. 维修人员添加处理记录。
9. 维修人员完成工单。
10. 系统通过 RabbitMQ 异步通知用户。
11. 用户评价工单。

## 巡检流程

管理员可以创建巡检计划。创建巡检计划后，系统会生成巡检任务。

巡检人员可以开始巡检，并提交巡检结果。

如果巡检结果正常，巡检任务完成。
如果巡检结果异常，系统会自动调用工单模块创建维修工单，工单进入待派单状态，并通过 RabbitMQ 通知管理员。

## 通知场景

RabbitMQ 主要用于异步通知消息，场景包括：

- 创建工单后通知管理员。
- 派单后通知维修人员。
- 自动派单后通知维修人员。
- 完成工单后通知用户。
- 巡检异常生成工单后通知管理员。

## Redis 使用场景

Redis 在系统中主要用于：

- 登录 token 存储。
- token 自动续期。
- 工单防重复提交。
- 维修人员接单分布式锁。
- 设备分页缓存。
- 设备详情缓存。
- Python Agent 多轮对话上下文保存。

## AI Agent 说明

Python FastAPI Agent 服务负责 AI 对话、大模型调用、Tool Calling、RAG 知识库检索和多轮上下文管理。

Java 后端 smart-ops-system 负责真实业务，包括用户、设备、工单、巡检、通知、统计、数据库、Redis 和 RabbitMQ。

当用户要查询真实业务数据或创建工单时，Agent 应调用 Tool，由 Tool 调用 Java 后端接口。

当用户询问系统规则、角色权限、工单流程、巡检流程、Redis 或 RabbitMQ 用途时，Agent 应使用 RAG 检索知识库，再基于资料回答。
